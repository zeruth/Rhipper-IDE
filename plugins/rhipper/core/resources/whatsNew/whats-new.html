What Rhipper is

Rhipper recompiles a Windows binary. It reads facts off the binary, applies them in headless Ghidra, exports the decompilation of every function, and translates it to C that compiles in one round. The port then runs next to the reference, so you can compare the two function by function.

The workbench gives that pipeline a home. It opens a Rhipper project, runs the steps, shows the state of the port, and takes you from a fault or a low score to the code that causes it. It is built on the open-source IntelliJ Platform.

What you can do in this release

▶Run the pipeline

Buttons beside the Run widget run one step, or the pipeline from a step to the end. Each step is a run configuration, so its output stays in the Run tool window.

☰See the project

The Rhipper tool window shows the state of each step, the corpus, the translated share, the fidelity of the port and its last runs.

⌕Find functions

The Functions tab filters 80,000 functions by name, address, state and fidelity. The Fidelity tab sorts the worst first, with a histogram you can click.

⇄Read every view

Open Ghidra's decompilation, the translated C or the disassembly of a function, from the gutter, the editor, a console link or Tools | Rhipper | Go to Address.

CEdit C with clangd

Completion, navigation, hover and diagnostics for C and C++, through clangd. The IDE keeps the diagnostics, so Claude can read them too.

⚙Get the tools

The IDE installs Rhipper, a Python environment, JDK 21, Ghidra and clangd for you, and offers new Rhipper releases. See Tools | Rhipper | Tools.

Claude and MCP

The IDE's MCP server gives Claude the Rhipper workflow. Claude reads the project, finds functions, compares Ghidra's C with the translation, runs pipeline steps in your Run tool window, and polls the fidelity report for regressions.

ToolWhat Claude can do with it
rhipper_projectRead the settings, the outputs and the state of each step.
rhipper_query_functionsFind functions by name, regex, address range, size, state, fidelity and differing calls.
rhipper_functionRead Ghidra's C, the translated C, the fidelity entry and the clangd diagnostics of one function.
rhipper_fidelity_changesCompare the fidelity report with the last snapshot: regressions, improvements, new low scores.
rhipper_clangd_diagnosticsGroup the clangd errors and warnings by code, to find a pattern of the translator.
rhipper_run_stepRun a pipeline step and wait for its end.
rhipper_scriptRun any Rhipper tool, such as shadow_diff.py, and read its output.

The Rhipper skill teaches Claude Code the rule of the project: fix a defect where it arises, never one function at a time. Add it with Tools | Rhipper | Install Claude Skill. Then ask, for example:

The port faults at startup. Find where it parts from the reference and tell me which fact is wrong.
Show me the twenty worst translated functions, group them by cause, and fix the most common one.

Get started

  1. Open a folder with a rhipper.json, or create one with File | New | New Rhipper Project.
  2. Let the IDE install what is missing when it asks, or open Tools | Rhipper | Tools.
  3. For Claude, turn on Settings | Tools | MCP Server, then add the Rhipper skill to the project.
  4. Run the pipeline with the buttons beside the Run widget, and watch the Rhipper tool window.

Roadmap

Installer and updates

A Windows installer on GitHub, and updates of the workbench from new releases.

One shared syntax tree

The decompilation, the translation and the IDE share one tree, with no round trips through text.

Ghidra inside the IDE

Ghidra and Rhipper run in the workbench, not as external tools, and the IDE runs only the steps that a change needs.

Side-by-side stepping

Step the reference and the port together, and stop at the first place where they part.

More toolchains and languages

More compilers and compile flags in, and more output languages out of the tree.
